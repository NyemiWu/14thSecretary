# skill 登记

**这一页是后续 agent / skill 相关内容的落点。** 新增 skill、改 agent 协作方式、
引入新的自动化，都更新到这里。

## agent 资产的三层

同一个知识在三个地方各有形态，**职责不同，别重复写**：

| 层 | 位置 | 给谁 | 什么时候读 |
|---|---|---|---|
| **机器入口** | 仓库根 `AGENTS.md` | 支持该约定的 agent 工具 | 自动加载 |
| **站点文档** | 本分区（`docs/agents/`） | 人 + agent，可搜索可链接 | 主动翻阅 |
| **skill** | `~/.workbuddy/skills/<名字>/SKILL.md` | agent 跨项目复用 | 任务匹配时自动加载 |

**同步规则**：改了[硬规则](constraints.md)，要一并看 `AGENTS.md` 和对应的 skill
有没有过期。**这三处不一致比缺失更有害。**

## 什么时候该新开一个 skill

**满足任意两条**就值得沉淀：

- 这件事会重复做（不是一次性的）
- 步骤超过 5 步，或涉及多个工具/系统
- 有非显然的坑（踩过一次，不记就会再踩）
- 换个人从零做需要重新摸索

**不值得沉淀**：一次性的迁移、纯查询、只对当前这条内容有效的判断。

## 什么时候该更新已有 skill

- skill 里的命令/路径/版本过期了
- 发现了更好的做法或新的边界情况
- skill 里写了但实际不成立的结论（**这种最危险，优先修**）
- 本次任务中被迫推断出的前提 —— 说明 skill 该写明它

## 登记模板

新增一条时，往上面的表里加一行，并在 skill 目录下留一句用途说明：

```markdown
| `<skill 名>` | <覆盖什么> | <跟本仓库什么关系> |
```

如果是**和本仓库无关**的通用 skill，也登记 —— 只是备注里写清"与本仓库无关"，
免得后面的人以为漏了。
