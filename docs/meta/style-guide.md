# 编辑规范

设定会长到几百条，所以约定要**现在**定，不要等写到一半再改。

## 目录

| 目录 | 放什么 | 文件名格式 |
|---|---|---|
| `canon/` | 世界设定、规则、术语 | `主题.md`，英文短横线 |
| `canon/<板块>/` | 同类设定的集合 | `条目名.md` |
| `bestiary/` | 赐名怪物条目 | `编号-英文短名.md`，编号三位数 |
| `tools/` | 可交互工具的介绍页 | 与 `assets/` 里的 HTML 同名 |
| `meta/` | 编辑规范与模板 | 固定 |
| `assets/` | 图片、附件、单文件 HTML | 英文短横线 |
| `stylesheets/` | 样式微调 | 固定 |

!!! danger "目录名和文件名一律用 ASCII"
    中文文件名在 URL 里会变成 `%E7%A7%98%E8%AF%AD` 这种，
    又长又难认，还会在跨平台同步时炸掉。
    **中文只出现在两个地方**：页面的 `# 标题`，和 `mkdocs.yml` 的 `nav`。

## 一条设定一个文件

不要把十来个条目塞进同一页。理由很实际：

- 侧栏导航才能长出树，而不是一长串同级条目
- 搜索命中后能直接落到那一条，而不是落进一页长文
- 两个人同时改不同条目不会冲突

单页超过 400 行，就该拆了。

## 页面骨架

```markdown
---
title: 页面标题
tags:
  - 分类标签
---

# 页面标题

一句话定义。

## 正文小节
```

`title` 会和 `nav` 里的名字保持一致。`tags` 用来做跨板块的横向聚合 ——
比如给所有涉及某一秘语的条目打同一个标签，就能反查哪些条目用到它。

## 链接

- **站内**：用相对路径 `[四段式真名](../canon/true-name.md)`。
  不要写 `/canon/true-name/` 这种绝对路径，绑定自定义域名或改仓库名时会全断。
- **跨条目引用**：第一次出现时给链接，后面重复出现就不用再链了。

## 提示块

Material 支持这些容器，按语义用，不要全用 `note`：

| 写法 | 用途 |
|---|---|
| `!!! note` | 补充说明 |
| `!!! tip` | 建议、捷径 |
| `!!! info` | 背景信息 |
| `!!! warning` | 需要注意的坑 |
| `!!! danger` | 会导致错误/失败的事 |
| `!!! abstract` | 摘要、属性表 |
| `!!! quote` | 引用设计原案 |
| `??? note` | 同上，但默认折叠 |

可折叠用 `???`，需要展开才看的细节一律折叠，页面会干净很多。

## 表格

参数、对照、清单一律用表格。这是这个库里最常用的结构，
[秘语体系](../canon/secrets.md) 就是范例。

## 版本与状态

写了一半的页面，在顶部加一条：

```markdown
!!! warning "草稿"
    本页尚未定稿。
```

不要留孤立的占位段落。要么整页不建，要么建了就把状态标清楚。
